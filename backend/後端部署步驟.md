# Google Sheet + Apps Script 後端部署步驟

跟著這份步驟在瀏覽器操作即可，全程用您自己的 Google 帳號，權限跟隱私都在您手上。

## 1. 建立 Google Sheet

1. 到 [sheets.google.com](https://sheets.google.com) 建立一份新的空白試算表。
2. 幫它取個名字，例如「班級經營儀表板 - 資料庫」。
3. 先不用手動加分頁或欄位，等一下用程式自動建立（步驟 4）。

## 2. 開啟 Apps Script 編輯器

1. 在剛剛的試算表裡，點選單「擴充功能」→「Apps Script」。
2. 會開一個新分頁，這是綁在這份試算表底下的 Apps Script 專案。

## 3. 貼上程式碼

1. 編輯器左邊有個 `appsscript.json`（如果沒看到，點左側齒輪圖示「專案設定」，勾選「在編輯器顯示 appsscript.json 資訊清單檔案」）。把這個專案內 `backend/appsscript.json` 的內容整份覆蓋貼進去。
2. 編輯器裡預設會有一個 `Code.gs`，把裡面的內容全部刪掉，貼上這個專案內 `backend/Code.gs` 的完整內容。
3. 存檔（Ctrl+S 或點選左上角儲存圖示）。

## 4. 建立資料表分頁

1. 在 Apps Script 編輯器上方的函式下拉選單，選擇 `setupSheets`。
2. 點「執行」。
3. 第一次執行會跳出 Google 帳號授權畫面，選您自己的帳號 →「進階」→「前往（專案名稱）(不安全)」→「允許」。這個警告是因為這是您自己寫的小工具、還沒送 Google 審核，不是真的有問題，只有您自己的帳號能執行它。
4. 執行完成後回到 Google Sheet，應該會看到自動多出 `Sessions` 跟 `SessionGroups` 兩個分頁，各有一列標題。

## 5. 部署成 Web App

1. Apps Script 編輯器右上角「部署」→「新增部署作業」。
2. 齒輪圖示選「網頁應用程式」。
3. 「執行身分」選「我」。
4. 「誰可以存取」選「所有人」（前端要用純 fetch 呼叫，沒有走 Google 登入，所以這裡必須開放；實際保護是靠程式碼裡的教師 PIN，不是靠這個存取權限）。
5. 點「部署」，會再跳一次授權確認畫面，照步驟 4-3 的方式允許。
6. 部署完成後會給您一個網址，格式類似：
   `https://script.google.com/macros/s/xxxxxxxxxxxxxxxxxxxxx/exec`
   複製這個網址。

## 6. 接回前端

打開 `docs/js/config.js`，把 `API_URL` 換成剛剛複製的網址：

```js
window.APP_CONFIG = {
  API_URL: '貼上您的網址'
};
```

**教師密碼不填在這裡**：`config.js` 只放 `API_URL`。密碼分別寫死在兩個地方，要同步改：`backend/Code.gs` 的 `TEACHER_PIN`（後端驗證用），跟 `docs/js/teacher.js` 開頭的 `TEACHER_PIN`（教師頁載入時自動送給後端，教師不用手動輸入）。這**不是真正的存取控制**，兩份都是公開檔案，改密碼只是換一組沒被公開討論過的字串，真正的保護要等之後接 Google 帳號登入。

## 7. 測試

1. 本機執行 `docs/start.ps1`（或 `python -m http.server`）打開網頁，開 `teacher.html`。
2. 一開頁應該直接看到「開始課堂」畫面，不需要輸入密碼。
3. 選班級、點「開始本節課」。
4. 回到 Google Sheet，`Sessions` 分頁應該立刻多一列資料，`SessionGroups` 分頁會依小組數量多出對應列數。
5. 在網頁上點幾次燈號、調整星等/💡，確認 Google Sheet 裡的資料有跟著更新。

## 之後要改程式碼時

Apps Script 編輯器裡的程式碼是「正式在跑的版本」，跟這個 repo 裡的 `backend/Code.gs` 是分開的兩份檔案。如果之後改了 `backend/Code.gs`（包含改密碼），要記得回到 Apps Script 編輯器手動貼上最新內容、重新部署，repo 裡的檔案不會自動同步過去。

**重新部署一定要走這條路：「部署」→「管理部署作業」→ 點現有部署項目旁邊的鉛筆（編輯）圖示 → 「版本」選「新版本」→「部署」。**

⚠️ **不要點「部署」→「新增部署作業」**——這個會建立一個全新網址，新程式碼是跑在那個新網址上，但 `config.js` 裡填的還是舊網址，會變成「明明部署了，網站卻還是連到舊版本」，這是最容易踩的坑。如果不小心點成這個，到「管理部署作業」把正確、最新的那個網址複製出來，貼回 `config.js` 的 `API_URL` 就能修正，不用整個重來。

## 常見問題

- **畫面一直顯示「無法連線到後端」**：檢查 `config.js` 的 `API_URL` 有沒有貼對、有沒有多空格；用瀏覽器直接開那個網址加 `?action=getCurrentSession`，應該要看到一段 JSON文字，不是錯誤頁面。
- **操作後顯示「教師密碼設定不一致」**：`docs/js/teacher.js` 跟 `backend/Code.gs` 的 `TEACHER_PIN` 對不起來，或後端還在跑舊版本。先用瀏覽器 Console 執行 `Store.setPin('隨便打的密碼'); Store.verifyPin().then(r => console.log(r));`——如果回傳 `unknown_action` 而不是 `invalid_pin`，代表後端還在跑舊版本（`verifyPin` 這個動作在舊版不存在）；去「管理部署作業」核對網址是不是跟 `config.js` 一致（見上面的⚠️ 提醒）。
- **改了 Code.gs 但前端行為沒變**：忘記重新部署了，或部署到了錯的網址，看上面「之後要改程式碼時」。
